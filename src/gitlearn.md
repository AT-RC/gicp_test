# Git 实用指令速查手册

本手册收录了日常开发中最常用的 Git 指令，以及一些在特殊场景下非常有用、方便后续查阅的高级指令。

---

## 💡 一、 日常开发最常用的核心指令（每天都会用）

### 1. 代码提交流程（“一键三连”）

在对代码做完修改后，按顺序执行以下指令进行保存和推送：

| 命令 | 作用 | 说明 |
| :--- | :--- | :--- |
| **`git status`** | **查看当前状态** | 确认哪些文件被修改了，哪些是新加的。 |
| **`git add .`** | **添加修改到暂存区** | `.` 代表添加当前目录下的所有改动。如果只想加单个文件：`git add 文件路径`。 |
| **`git commit -m "提交说明"`** | **保存本地快照** | `-m` 后面是本次改动的简短描述。**这是本地保存的最关键步骤**。 |
| **`git push`** | **推送至远程仓库** | 将本地的提交记录推送到 GitHub / Gitee 等云端仓库。 |

### 2. 状态与差异查看

* **`git status -u .`**
  查看当前目录下具体有哪些文件被修改或未被跟踪（`-u` 会展开文件夹显示里面的具体文件）。
* **`git diff`**
  查看工作区代码相比于上一次提交，**具体修改了哪些行**（红字为删掉的，绿字为新增的）。
* **`git log --oneline`**
  以极简的单行列表形式查看历史提交记录（每行开头是版本号缩写）。
* **`git pull`**
  从远程仓库拉取最新代码并合并到本地（每天开始写代码前的第一件事）。

## 🌿 二、 分支开发指令（团队协作或多任务并行）

在开发新功能（比如写新算法、调新串口协议）时，最好在独立分支上开发，避免把主分支 `master` / `main` 搞乱。

* **`git branch`**
  查看当前本地所有的分支（前面带 `*` 的是当前所在分支）。
* **`git checkout -b <分支名>`**
  创建并立即切换到一个新分支（例如：`git checkout -b gicp-fix`）。
* **`git checkout <分支名>`**
  切换到已有的分支（例如：`git checkout master` 切换回主分支）。
* **`git merge <分支名>`**
  将指定分支的代码合并到当前所在的分支（通常在 `master` 分支下运行此命令，合并开发好的新功能）。

## 🛠️ 三、 备忘与高级指令（不常用，但关键时刻能救命）

这些命令平时用得少，但遇到代码写乱了、需要紧急保存或者版本冲突时，可以作为工具书查阅。

### 1. 撤销与回滚（时光倒流）

> [!WARNING]
> 使用带有 `--hard` 参数的命令时要格外小心，因为它会彻底抹去你的本地修改！

* **`git restore <文件名>`**
  撤销工作区中该文件的所有未提交修改（恢复成上次保存的样子）。
* **`git restore --staged <文件名>`**
  把运行了 `git add` 的文件撤回，重新变回未暂存的状态。
* **`git reset --soft HEAD~1`**
  撤销上一次的 `commit`，但**保留**你写好的代码（代码还在，只是退回到 `commit` 之前的暂存区状态）。
* **`git reset --hard <版本号>`**
  彻底回滚到历史上的某个版本，**并丢弃**该版本之后所有的代码改动（版本号通过 `git log` 查看）。

### 2. 暂存代码（“下班/临时切换任务”）

当你代码写到一半还没写完，不能提交，但又必须切换到别的地方去修改紧急 Bug 时：

* **`git stash`**
  把当前写了一半的改动临时“打包存起来”，让工作区瞬间变回干净状态。
* **`git stash pop`**
  做完别的事后，把临时存起来的改动重新“吐出来”，继续之前的开发。
* **`git stash list`**
  查看当前有多少个临时暂存。

### 3. 分支清理与维护

* **`git branch -d <分支名>`**
  删除一个已经合并过的本地分支。
* **`git branch -D <分支名>`**
  强制删除一个未合并的分支（会丢失该分支上所有未合并的代码）。
* **`git remote -v`**
  查看当前本地仓库连接了哪些远程仓库的链接。

## 🎬 四、 实战演练示例（保存、回溯、忽略的一步步操作）

下面以你在开发机器人项目时的**真实场景**为例，演示这三个操作的具体命令流：

### 场景一：保存（Save）—— 把我刚写好的代码安全存入“时光机”

假设你刚刚修改了 `small_gicp_relocalization.cpp`，代码编译成功了，你想保存：

1. **查看状态**：
   ```bash
   git status .
   ```
   *Git 会用红字提示你：`modified: src/slam_and_odom/small_gicp_relocalization/src/small_gicp_relocalization.cpp`*
2. **将该文件加入“暂存区”（打包）**：
   ```bash
   git add src/slam_and_odom/small_gicp_relocalization/src/small_gicp_relocalization.cpp
   ```
   *(或者想省事，直接 `git add .` 把所有修改一起打包)*
3. **提交快照（存档并备注说明）**：
   ```bash
   git commit -m "fix: 修复 GICP 的死锁和多线程数据竞跑问题"
   ```
   *此时，你刚才写的代码就安全地保存在本地 Git 仓库历史中了，哪怕以后你把这文件误删了，也能随时找回来。*

---

### 场景二：回溯（Rollback）—— 代码写崩了/误删了，想要还原

假设你在修改 `sensor_scan_generation.cpp` 时手抖误删了十几行，或者运行报错，想退回到上一步：

* **情况 A：你还没有运行 `git add` 和 `git commit`**
  直接丢弃当前所有未保存的修改，恢复成上一次保存的样子：
  ```bash
  git restore src/perception/sensor_scan_generation/src/sensor_scan_generation.cpp
  ```
  *文件内容会瞬间自动变回上次 commit 时的状态。*

* **情况 B：你想回到几小时前甚至几天前的历史版本**
  1. 先用极简模式查看以前的历史提交记录：
     ```bash
     git log --oneline
     ```
     *屏幕会输出类似如下的历史列表：*
     ```text
     a1b2c3d (HEAD -> master) fix: 修复 GICP 的死锁和多线程数据竞跑问题
     e4f5g6h feat: 实现了雷达里程计的计算
     j9k8l7m init: 初始化工作空间
     ```
  2. 此时如果你想回到 `e4f5g6h` 的版本（即做 GICP 修复之前的版本）：
     * **安全模式（临时回去看看，代码不丢失）**：
       ```bash
       git checkout e4f5g6h
       ```
       *(看完后，运行 `git checkout master` 即可一键返回最新状态)*
     * **彻底回滚模式（彻底放弃 `a1b2c3d` 的改动，慎用！）**：
       ```bash
       git reset --hard e4f5g6h
       ```

---

### 场景三：忽略（Ignore）—— 让编译出来的垃圾文件不打扰 Git

你编译 ROS 2 时会生成 `build/`、`install/`、`log/` 等文件夹，里面有成千上万个编译中间文件。如果用 `git status` 看，会密密麻麻一大片，干扰视线。

1. **创建 `.gitignore` 文件**（放在项目根目录 `/home/xjh/Desktop/at_rc/` 下）。
2. **在文件里写入你要忽略的文件夹名字**：
   ```text
   build/
   install/
   log/
   ```
3. **查看效果**：
   运行 `git status .`。此时你会发现，那三个文件夹里所有的红字文件全部消失了！Git 已经对它们“视而不见”，只留下了你真正写好的代码。
